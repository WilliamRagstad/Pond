# Configuration and templates

## Configuration file

The CLI accepts `Pond build <config.json>` or `Pond build /c <config.json>`.
The file is a JSON object. Unknown fields and missing required values fail the
build. Paths may be absolute; relative paths are resolved against the directory
containing the configuration file, not the shell's working directory.

This is the complete, tested [example configuration](../examples/basic/config.json):

```json
{
  "ArticlesPath": "articles",
  "TemplatesPath": "templates",
  "StylesPath": "style",
  "OutputPath": "site",
  "DefaultArticleInfo": { "Template": "page" }
}
```

| Field | Required behavior | Value generated by `init` |
| --- | --- | --- |
| `ArticlesPath` | Existing directory; recursively reads files with a `.md` extension, case-insensitively. Other files are ignored. | `articles` |
| `TemplatesPath` | Existing directory used to resolve article templates. | `templates` |
| `StylesPath` | Existing directory; recursively copies all its files to `OutputPath/style/`, preserving relative paths and bytes. May be empty. | `style` |
| `OutputPath` | Destination for generated pages; directories are created as needed. Must not equal, contain, or be inside an input directory. | `site` |
| `DefaultArticleInfo` | Required object with a nonempty `Template` string, used for articles without metadata. | `{ "Template": "index" }` |

These are required fields, **not implicit defaults** when loading JSON. `init`
serializes its defaults into a new config. There are no URL, theme, minification,
watch, asset-directory, or stylesheet-injection settings.

`articles/guide/start.md` becomes `site/guide/start.html`. Source traversal is
sorted ordinally. The builder overwrites matching output files but does not remove
stale files after articles are renamed or deleted. Use a fresh output directory
for a clean publication. A failed build may leave partial output; only publish a
successful build.

## Article metadata

An article can select another template with a leading HTML comment containing a
JSON object, before its first heading:

```markdown
<!-- { "Template": "detail.html" } -->

# Details

[Home](../../index.html)
```

This is the form used in
[`articles/guide/deep/details.md`](../examples/basic/articles/guide/deep/details.md).
Only a leading JSON HTML comment is recognized as metadata; ordinary braces in
Markdown content do not select a template. Recognized invalid JSON, unknown
metadata fields, or an empty/missing `Template` fail the build. Metadata replaces
the default object; it is not merged. A standalone metadata comment is omitted
from rendered content.

For `Template: "page"`, Pond tries `TemplatesPath/page` first, then
`TemplatesPath/page.html`. `"detail.html"` therefore works directly. Missing
selected templates fail the build with the article and template path.

## Links and assets

Write links to the **output names**, e.g. `[Guide](guide/start.html)` from
`index.md`, and `[Home](../index.html)` from `guide/start.md`. Pond does not rewrite
`.md` links or generate heading IDs. Fragment links need IDs supplied by your
template. Relative URLs are resolved by the browser against the output page.

Only `StylesPath` is copied, always under the output directory's literal `style/`
subdirectory. It can hold CSS, images, and other static files. Files alongside
Markdown are not copied. Templates must include stylesheet and image URLs;
Pond does not inject them. The deeply nested details page uses
`href="../../style/site.css"`.

## Template model

Tags and variable names are case-sensitive. HTML outside tags is preserved,
including whitespace. `{{ expression }}` evaluates a C# expression using
DynamicExpresso and inserts its string representation without HTML escaping or
trimming. Null results produce no text. Use trusted templates and content:
expressions are executable logic, and template output is not an HTML sanitizer.

| Global | Value |
| --- | --- |
| `TITLE` | Text of the first level-one Markdown heading, or null if absent. |
| `ELEMENTS` | Array of Markdown blocks in source order, including headings, excluding standalone comments. |
| `CHAPTERS` | Array of chapters split at level-one and level-two headings. Each has `Title` and `Elements` fields. |

Chapter elements exclude the heading that starts the chapter. Chapters with no
content blocks are omitted. Content before the first heading can form a chapter
with a null title. Use `ELEMENTS` when you want to retain all headings and their
levels; use `CHAPTERS` when the template should lay out sections itself.

The [default fixture template](../examples/basic/templates/page.html) renders every
block through the existing `ToHtml()` extension method:

```html
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>{{ TITLE }}</title></head>
<body>
{% for element in ELEMENTS %}
{{ element.ToHtml() }}
{% endfor %}
</body>
</html>
```

Loops use `{% for variable in expression %}` and require an enumerable value.
Conditions use `{% if expression %}` and require a boolean value. Close them with
`{% endfor %}` / `{% endif %}`, or the generic `{% end %}`. Blocks can nest; loop
variables are scoped to their loop body and nested loops may shadow them. The
[alternate template](../examples/basic/templates/detail.html) exercises chapters,
a condition, and nested loops.

Unclosed tags, missing/mismatched closing actions, unknown actions, empty tags,
and failed expression evaluations stop the build. Syntax diagnostics include a
template path and zero-based character offset; evaluation diagnostics identify
the expression. `else`, assignments, filters/pipes, includes, and template
inheritance are not implemented. Django/Jinja resemblance is syntax inspiration,
not compatibility.

## Reproducibility

The SDK selection and NuGet lock file are committed. Use `dotnet restore
--locked-mode` to prevent dependency resolution changes. The checked-in fixture
uses LF input files, constant content, relative URLs, and deterministic
expressions; generated HTML is UTF-8 without a BOM and uses LF newlines. Styles
are copied byte-for-byte. The verification script checks identical file lists
and SHA-256 hashes after both clean and incremental rebuilds.

Reproducibility assumes identical inputs and toolchain. Custom expressions that
read time, random values, external state, or use culture-sensitive formatting can
produce varying output. Pond does not make arbitrary C# expressions deterministic.
